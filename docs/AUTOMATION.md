# 향후 자동화 연결 메모

현재 작동 대상으로 준비한 경로는 Pages CMS 저장 → GitHub 기록 → 홈페이지 배포입니다.
Dropbox·Slack·Claude·PubMed 자동화는 연결 전이며 자동 실행하지 않습니다.
원본 scripts/는 개발용 초안으로 보존했습니다. docs/automation-prototype.yml.txt는 참고용 원본이며 실행되지 않습니다.

## 연결 순서
1. 수동 편집으로 사이트를 먼저 운영하고 영문 이름·모집 조건·사진·논문을 확인합니다.
2. Dropbox에 홈페이지 전용 inbox를 만들고, 해당 범위만 접근하는 앱을 별도 설정합니다.
3. Claude API로 메모를 한영 초안으로 변환합니다. Claude 앱 구독과 API 사용료는 별도이며, 앱 커넥터의 파일 쓰기 지원은 연결 시 확인해야 합니다.
4. 초안을 main에 바로 쓰지 않고 검토용 변경 제안(Pull request)으로 저장합니다.
5. 담당자가 확인하여 Merge하면 기존 배포가 실행되게 합니다. Slack 알림은 별도 연결합니다.

## 원본 스크립트에서 연결 전에 해결할 항목
- 모델 출력에 필수 항목·URL·날짜·고유 ID 검증을 적용해야 합니다.
- Dropbox/Slack 목록의 다음 페이지까지 읽어야 합니다.
- 저장 성공 전에 Dropbox 원본을 이동하거나 Slack 처리완료 표시를 하지 않아야 합니다.
- 실패한 Slack 메시지가 다음 실행에서 누락되지 않도록 상태 저장을 바꿔야 합니다.
- 구성원 부분 수정 시 기존 사진·소개를 덮어쓰지 않도록 병합해야 합니다.
- PubMed 동명이인과 중복 논문을 검토해야 합니다. selected=false는 비공개 설정이 아닙니다.
- GITHUB_TOKEN으로 만든 커밋은 일반 push 배포를 다시 실행하지 않으므로, 승인 후 merge 또는 명시적인 배포 호출이 필요합니다.

계정 연결·권한·비용·오류 복구를 실제로 검증하기 전에는 이 초안을 운영 자동화로 사용하지 마세요.
